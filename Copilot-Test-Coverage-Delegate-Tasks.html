Test Coverage · 03

Self-Healing

04 / 09

A failing test is useful feedback. The agent can read the command output, diagnose the mismatch, adjust its change, and rerun checks.

01 · FAIL

Run tests

Capture the failing assertion or error.

02 · READ

Inspect evidence

Trace output to the changed behavior.

03 · FIX

Make a correction

Update the relevant code or test.

04 · VERIFY

Rerun checks

Confirm the fix and check regressions.

Example feedback

Expected: 0.00
Received: -0.00
Agent identifies negative-zero normalization, updates the targeted behavior, and reruns the test.

Keep the loop bounded

Ask for a specific test command and a stopping condition.

Review the diff, test quality, and any production-code edits.

Do not treat a green run as proof that behavior is correct.

Delegate Tasks · 03

Custom Agents

07 / 09

Package a repeatable job as a role with a clear scope, the tools it needs, and explicit boundaries. Use a small real task to test whether its behavior matches the role.

Create in VS Code

Open Chat: Open Customizations, then choose Agents → New Agent (Workspace).

Save a .agent.md profile under .github/agents/.

Select the agent and test it on a small, reviewable change.

Limit tools to the job’s needs. Workspace agents are reusable with the repository.

.github/agents/test-specialist.agent.mdWORKSPACE AGENT
---
name: test-specialist
description: Adds focused tests for uncovered behavior.
tools: [read, search, edit, runInTerminal]
---

Add or update tests only.
Do not modify production code.
Target uncovered branches, not only happy paths.
Run the focused test, then report results.
Stop when the requested coverage target is met.
